# ADR-0007 — MCP 연결 토큰

- 소유 문서: [server.md](../server.md)
- 근거: 레인 작업 지시("연결별 토큰(이름·만든 시각·마지막 사용·폐기)을 서버에 해시로 저장하고 만들 때 한 번만 보여주는 방식", "AGENT_TOKEN 원문을 화면에 노출하지 말 것", "토큰 만들기·폐기는 로컬 리스너 또는 공개의 macOwner 사람만"), [설정창 계획](../../devlog/_plan/261107_settings_panel/000_plan.md).

## 결정 기록

- 목적: 설정 › 연결에서 에이전트마다 MCP 연결을 만들고 끊을 수 있게 해요. 사람이 화면에서 복사해 에이전트 설정에 넣어요.
- 제약: `AGENT_TOKEN` 은 서버 env 비밀값이라 화면에 보여줄 수 없어요. 공개 /mcp 는 Cloudflare Access 뒤라 원격 에이전트는 Access 서비스 토큰도 필요하고, Cloudflare 설정은 이 레인에서 바꾸지 않아요. 기존 `AGENT_TOKEN` 연결은 그대로 동작해야 해요.
- 선택: 연결 토큰 `dbt_<base64url 32바이트>` 를 만들 때 한 번만 응답하고, 서버에는 SHA-256 해시와 앞부분·이름·만든 사람·시각만 저장해요. /mcp 에서만 통하고, 만들기·목록·폐기는 맥 주인 사람만 해요. 설계는 [MCP 연결 토큰](../../docs/internals/mcp-tokens.md)이에요.
- 검토한 대안: `AGENT_TOKEN` 을 화면에 보여주기(지시로 금지, 끊으려면 모든 연결을 바꿔야 함), 토큰 원문을 암호화해 저장하고 다시 보여주기(복호화 키도 서버에 있어 DB 유출 시 이득이 작고, 다시 보여줄 필요가 없음), OAuth(Claude·Cursor·Codex 가 지원하지만 Access 뒤 공개 주소에서 인증 서버와 동적 등록을 새로 열어야 해 범위가 큼), 느린 비밀번호 해시(256비트 무작위 토큰에는 이득 없이 요청마다 비용).
- 영향: 새 테이블 `mcp_tokens`(서버 시작 때 만들고 기존 데이터는 바꾸지 않음), REST `/api/mcp-tokens`, /mcp 인증에 해시 조회 추가, 계약 `packages/contracts/src/settings.ts`. 웹 설정 › 연결에 목록·만들기·폐기. 만료·권한 범위는 다음 결정으로 남겨요.
