# ADR-0010 — iOS 정보 구조

- 소유 문서: [mobile.md](../mobile.md)
- 근거: 사용자 요청 "지금 ios 앱에서도 웹에서 되는 모든 경험을 할 수 있도록 재설계해서 … 불필요한 왼쪽 선 같은 건 좀 전부 제거해줘", 레인 0 작업 지시, [iOS 동등 로드맵](../../devlog/_plan/261107_ios_parity/000_roadmap.md).
- 설계 설명: [모바일 IA](../../docs/internals/mobile-ia.md)

## 결정 기록

- 목적: iOS 에서 웹의 모든 경험(홈, 빠른 추가, 전체 목록, 일 상세, 목표, 결정, 문서, AI, 검색, 설정, 운영 순회)을 할 수 있게 하고, 여러 레인이 동시에 만들 수 있는 화면 구조와 파일 경계를 정해요.
- 제약: 같은 REST 계약과 서버 권한 규칙. 새 네이티브 모듈 없이(TestFlight 빌드 절차 그대로). 레인 1~3 이 같은 파일을 고치지 않게.
- 선택:
  - 탭은 홈·전체·문서·AI·검색. 설정은 홈 머리 톱니와 검색 결과로. 검색이 동작하기 전까지는 지금의 설정 탭을 둬요.
  - 탭마다 native-stack 쌓기, 공용 상세 라우트는 모든 탭 쌓기에 등록. 필은 탭 루트에서만 보임.
  - 데이터는 "서버 주소 + 로그인 주체" 별 공용 쿼리 캐시(주체가 바뀌면 비움), 쓰기 중·뒤 늦은 읽기는 버림, 판 항목은 낙관적 쓰기와 실패 시 되돌림. 쓰기 실패는 409 `ConflictError`(본문 전체)·거절·결과 불명으로 나눠요. 노트는 서버 `markdownEditable`(엄격 변환 + 서식 모델 비교)이 true 일 때만 iOS 가 md 로 고치고, 저장은 write replace + expectedVersion 과 웹 NoteSaver 와 같은 뜻의 상태 기계(src/notes/)로 해요.
  - 스와이프는 PanResponder·Animated 로 만들고 길게 누르기는 iOS 동작 시트(ActionSheetIOS).
  - 왼쪽 장식선 금지, 위계는 여백·글자 무게·바탕. 모바일 소스 시험으로 지켜요.
  - 보드 캔버스는 확대·축소 캔버스 화면(`Board`)으로 모바일에 둬요.
- 검토한 대안:
  - 설정 탭 유지: 설정은 매일 쓰는 곳이 아니고, ⌘K 에 해당하는 전역 검색 입구가 모바일에 없어요. 웹이 운영 순회를 주 메뉴에서 뺀 기준과도 어긋나요.
  - 검색을 탭이 아닌 각 화면 머리 검색창으로만: 목록 안 찾기는 머리 검색창으로 하지만, 화면·명령·설정까지 찾는 전역 입구는 한 자리가 있어야 웹 ⌘K 와 같아져요.
  - 공용 상세를 루트 쌓기 하나에 두기(탭 위로 덮기): 탭을 오가면 쌓인 자리를 잃고, 다른 탭에서 연 상세가 서로 섞여요.
  - 스와이프에 react-native-gesture-handler: 새 네이티브 모듈이라 빌드와 TestFlight 를 다시 맞춰야 해요. 행 스와이프 하나는 RN 기본 PanResponder 로 충분해요.
  - 보드 캔버스를 모바일에서 빼기: 처음 계획이었으나 감사에서 "웹에서 되는 모든 경험" 요청과 어긋난다는 지적을 받아 버렸어요. 메모·글·영역·연결과 배치는 웹 보드에만 있어요.
  - 노트 편집 가능을 클라이언트가 HTML 로 판정(레인 1 계획): 정규식·작은 파서로 웹 편집기의 구조 검사를 대신할 수 없고 서버에 이미 엄격 변환기가 있어, 서버 한 곳에서 판정해요(코디네이터 결정).
  - 캐시를 서버 주소로만 나누기: 같은 서버에서 계정을 바꾸면 앞 계정 데이터가 실패 시 "마지막 값"으로 남을 수 있어 버렸어요.
- 영향: 레인 1~3 은 자기 `features/` 폴더와 `screens.tsx` 만 고쳐요. 라우트·탭·공용 부품·API 훅 변경은 레인 0 이 정한 파일에서 PR 에 적어 해요. 웹 쪽 왼쪽 선(홈 결정·메인 칸, 일 상세 기록, 대화 인용, 마크다운 인용)은 이 결정의 범위 밖이라 그대로예요.
