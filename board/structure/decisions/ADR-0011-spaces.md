# ADR-0011 — 할 일 공간(개인·회사)

- 소유 문서: [server.md](../server.md)
- 근거: 사용자 요청 "방향판에 개인용 회사용을 일단 태스크를 구분할 수 있게 해서 설계를 계속하는 스레드 devlog 에 기록하고 한번 해보자"(2026-11-07), [엔터프라이즈 로드맵](../../devlog/_plan/261107_enterprise/000_roadmap.md)의 D-1, [주기 1 계획](../../devlog/_plan/261107_enterprise/010_cycle1_spaces.md).
- 설계 설명: [공간](../../docs/internals/spaces.md)

## 결정 기록

- 목적: 할 일·목표·사건을 개인 것과 회사(워크스페이스) 것으로 나눠 보고, 나중에 여러 사람이 들어올 워크스페이스의 첫 모양을 정해요.
- 제약: 기존 데이터는 개인이고 이행은 칸 추가뿐(쓰기 백필 없음). 일 주소 `item:<판>:<id>` 에 노트·연결·태그·거울 경로가 묶여 있어 바뀌면 안 돼요. 공간을 모르는 옛 클라이언트(iOS 배포본)의 PUT 이 공간을 지우면 안 돼요.
- 선택: 공간은 일의 속성이에요. `items.space`·`signals.space` 칸(NULL = 개인)과 `workspaces` 표(`ws_` + 12 hex). API 값은 `personal` 또는 워크스페이스 id. 공간을 보내지 않은 쓰기는 기존 값을 지키고, 모르는 값은 거절해요(조용히 개인으로 바꾸지 않음). 같은 제목 일 판정·결정 질문 ref·순회 카드 key 는 공간 안에서만 같아요.
- 검토한 대안: 회사 판으로 항목 옮기기(ref 가 바뀌어 노트·연결·태그·거울을 모두 옮겨야 함), 태그로만 구분(권한·필터·순회 규칙의 기준이 될 수 없고 사람이 지우면 사라짐), 판 종류만 기준(개인 판 하나뿐인 지금 데이터를 나눌 수 없음).
- 영향: 서버 `apps/server/server/spaces.ts`, 항목 쓰기·`/api/act`·운영 순회·사건·문서 검색(`space`)·MCP 스키마, 계약 `Space`·`Item.space`·`Signal.space`(선택 필드), 웹 공간 보기·빠른 추가 공간·일 화면 공간. 문서 층 키(`owner`)를 범위로 바꾸는 일은 [주기 3](../../devlog/_plan/261107_enterprise/030_cycle3_pilot_members.md)에 남겨요.
