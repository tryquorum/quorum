# ADR-0012 — 파일럿 인스턴스의 Google 로그인과 허용 목록

- 소유 문서: [server.md](../server.md)
- 근거: 사용자 지시(코디네이터 전달, 2026-11-07) "도메인은 newa.lidgeai.com 으로 로그인 가능하게 neuralarcade.ai 도메인 사람들이, 이슈 보내기 버튼도 만들고, 클플 말고 구글 로그인 붙여놓으면 더 좋을 듯", "jun@lidge.ai 랑 b@devfiance.ai 도 허용하고 admin 이 추가 허용 관리 할 수 있게도 설정해봐". 로드맵 [D-3·D-5](../../devlog/_plan/261107_enterprise/001_decisions.md).
- 설계 설명: [파일럿](../../docs/internals/pilot.md), 운영 절차: [파일럿 인스턴스](../../docs/operations/pilot-instance.md)

## 결정 기록

- 목적: 뉴럴아케이드 사람들이 따로 계정을 만들지 않고 회사 Google 계정으로 들어와 회사 공간 일을 보고 이슈를 보내게 해요.
- 제약: 개인 방향판(3070·direction.lidgeai.com, Cloudflare Access)과 데이터·프로세스가 섞이면 안 돼요. 허용 대상이 여러 도메인(neuralarcade.ai, lidgeai.com, lidge.ai, devfiance.ai)이에요. 비밀은 저장소 밖에만 둬요.
- 선택: 같은 코드의 별도 인스턴스(별도 DB·거울·포트·launchd·터널). `AUTH_MODE=google` 일 때 서버가 OIDC authorization code + PKCE 로 직접 로그인시키고(state·nonce, Google JWKS RS256 서명, iss·aud·exp·nonce·email_verified 검증), 들어올 수 있는지는 서버 DB 의 허용 목록(이메일·도메인)과 멤버 비활성으로만 판정해요(hd 는 쓰지 않음). env 의 허용·관리자 목록은 첫 시작 때의 씨앗이고 그 뒤 원본은 DB. 세션은 무작위 토큰의 해시를 DB 에 두고 HttpOnly·Secure·SameSite=Lax 쿠키로 주며, 허용 목록·비활성을 요청마다 다시 봐요. 역할은 관리자·멤버 둘이고 멤버는 회사 공간만 써요. 마지막 관리자는 강등·비활성·허용 해제할 수 없어요. 바꾼 것은 감사 기록에 남아요.
- 검토한 대안: Cloudflare Access 로 Google IdP 붙이기(사용자 지시로 앱 자체 로그인, Access 앱·정책을 새로 만들지 않음), hd 로 도메인 제한(여러 도메인과 개별 이메일을 받을 수 없음), 지금 인스턴스에 멤버를 들이기(개인 데이터와 맥 주인 권한이 섞임), 서버 쪽 비밀 없는 PKCE 공개 클라이언트(Google 웹 클라이언트는 비밀을 요구).
- 영향: `apps/server/server/google-auth.ts`·`access.ts`·`pilot.ts`·`issues.ts`, 표 `auth_sessions`·`access_rules`·`members`·`access_audit`·`issues`·`file_uploads`, 웹 설정 › 멤버·접근과 이슈 보내기·내 이슈. Access 모드(개인 방향판)는 바뀌지 않아요. 로그인 대기 값은 처음에 표(`auth_pending`)였다가 최종 리뷰 2 뒤 암호화 쿠키로 옮겼어요(무인증 요청이 서버 저장을 늘리지 않게).

## 보안 리뷰 뒤 보탠 결정(2026-11-07, 135c478 리뷰)

- 권한은 판과 항목 공간을 함께 봐요. 파일럿 멤버는 소유와 무관하게 회사 판의 워크스페이스 공간 항목만 읽고 써요(상태·변경·내보내기·일 검색·상세·연결·기록·고치기). 사건 칸·문서·AI 대화는 멤버에게 없어요. 역할은 요청마다 다시 봐서 강등 직후의 기존 세션도 멤버로 다뤄요.
- 회사 판의 공간 없는(NULL) 항목은 계약대로 개인이에요(2회차 리뷰로 바꿈. 1회차 고침의 자동 백필은 개인 글을 사람 뜻 없이 회사에 공개할 수 있어 뺐어요). 멤버에게 보이지 않고, 관리자가 회사 공간으로 옮길 때만 공개돼요. 파일럿 회사 판에 개인 공간 항목을 새로 두거나 옮기는 것은 관리자도 거절해요.
- 파일럿에서 `AGENT_TOKEN` 은 꺼요. 연결 토큰은 요청마다 만든 사람이 허용된 활성 관리자인지 보고, 강등·비활성·허용 해제 때 그 사람의 토큰을 폐기해요.
- 이슈 본문은 공유 할 일의 기록에 넣지 않아요. 보낸 사람과 관리자만 봐요. 옛 기록 자동 정리는 하지 않아요('이슈(' 로 시작하는 사람 글까지 지울 수 있어서). 1회차 배포 때 파일럿 DB 에서 정리된 1건은 배포 전 백업과 비교해 이슈 표 원문·보낸 사람과 정확히 같은 실제 이슈 기록이라 그대로 둬요.
- 파일럿은 로컬 리스너도 Google 세션·관리자 연결 토큰만 받고 `DEV_LOCAL_USER` 를 버려요. 본문은 다 받은 뒤 사람·역할을 보고, 접근 관리 변경·연결 토큰 만들기는 바꾸기 직전에 권한을 다시 보며 바꾸기·폐기를 한 트랜잭션으로 해요.
- 회사 공간 일의 노트·태그·속성·색인은 워크스페이스 범위(owner 칸에 워크스페이스 id)에 둬요. 멤버는 일 상세에서 읽고, 관리자는 문서 검색에서 회사 공간을 골라 찾아요. 사람별 범위 키 전체 이행(주기 3)의 첫 부분이에요.
- 최종 리뷰(e15f353) 뒤: 공간 옮기기는 관리자만, 문서 범위가 바뀌는 이동은 그 일에 노트·태그·속성이 있으면 거절해요(범위 이전은 주기 3 의 범위 키 이행에서 한 트랜잭션 이전으로 만들어요). 인증 전에는 본문을 받지 않고 경로별 본문 상한을 둬요. 운영 순회는 파일럿에서 끄고 개인 Aside 연결 주기에 실행별 인증된 보고 경로로 다시 열어요.
- 회사 공간으로 만드는 AI·운영 순회 할 일은 회사 판에 둬요. 같은 제목·key 판단도 그 판·그 공간 안에서 해요.
- Google 공개키는 1시간마다 다시 받고, 받지 못하면 12시간까지만 마지막 목록을 믿어요.
