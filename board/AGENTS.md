# 방향판

방향판은 사람이 할 일과 결정을 한곳에서 살피는 개인 보드예요. 사람의 글을 보호하고, SQLite를 원본으로 삼아 마크다운 거울을 만들어요. 같은 일을 두 번 만들지 않고, 어디서나 AI에 물을 수 있어야 해요. 웹·모바일·MCP·REST는 같은 일을 만나는 입구예요.

## 작은 용어집

- **일**: 할 일·목표·사건 등 상세와 노트로 살피는 대상이에요.
- **할 일**: 판의 실행할 항목이에요. **목표**: 기한 등을 가진 판의 목표예요.
- **사건(signal)**: 수집기나 AI가 보낸 변화·완료·결정 요청이에요. **칸(lane)**: 사건을 주의가 필요한 방식에 따라 나눈 자리예요.
- **판(board)**: 항목을 담는 보드예요. 개인 판과 회사 판이 있어요.
- **문서**: 일·사건·대화의 노트나 독립 문서를 탐색하는 단위예요. **ref**: 그 대상을 가리키는 주소예요.
- **노트**: 대상에 붙은 사람이 고치거나 AI가 제안하는 글이에요. **거울**: DB 내용을 밖에서 읽을 수 있도록 만든 마크다운 사본이에요.
- **AI 실행(run)**: 질문이나 초안 생성 한 번이에요. **대화(thread)**: 이어 묻는 실행의 묶음이에요.
- **운영 순회(ops sweep)**: 저장한 지시에 따라 주기적으로 영역을 살피고 보고하는 AI 실행이에요. **수집기**: 외부에서 사건을 보내는 주체예요. 연결된 수집기와 예시 데이터는 구분해요.

## 다치는 세 가지 길

1. 실제 `data/board.db`와 `data/vault`에 쓰지 마세요. 테스트는 격리된 복사본이나 메모리 DB를 써요. 서버는 시작만 해도 DB·거울을 바꿀 수 있어요.
2. 사용 중인 3070 서버를 재시작하지 마세요. `bun --watch`는 파일 변경에 재시작하며 진행 중 AI를 끊어요. 이름 패턴으로 프로세스를 죽이지 마세요.
3. `.env.local`과 `AGENT_TOKEN` 같은 비밀값을 기록하거나 올리지 마세요. 클라이언트에 서버 origin을 굳히면 다른 기기 연결이 깨져요.

## 모든 입구 확인

변경이 닿는 웹·모바일·REST `/api/act`·MCP `/mcp`·운영 순회를 확인해요. 공유 계약은 `packages/contracts`(`docs.ts` 문서 층, `api.ts` API 응답 타입)에 있고 서버·웹·모바일이 같은 파일을 import 해요. 계약을 바꾸면 세 곳이 함께 따라와요. 한 입구에서의 성공이 다른 입구의 증거는 아니에요.

## 개발과 검증

변경의 범위와 데이터·인증·공개 계약 위험에 맞춰 검증해요. 사람 글, 오래된 클라이언트, 실패와 충돌을 살펴요. 근거 없는 완료 주장을 하지 않고 실행하지 않은 검사는 `NOT RUN`으로 적어요. 기존 내보내기를 지우기 전에 사용처를 찾고, 사용자 데이터 삭제·배포·푸시는 권한을 확인해요. 작업 중인 다른 레인의 파일을 건드리지 않아요.

통합 검사는 루트 `bun run check`예요. lint(oxlint와 저장소 규칙·코드 예산), typecheck(서버는 파일별 타입 오류 예산, 웹·모바일·계약은 tsc), test(서버·모바일·규칙), knip을 차례로 돌려요. 웹 빌드는 `bun run build`예요.

## 문서 규칙

사용자가 하는 일은 `docs/user/`, 개발·배포 절차는 `docs/operations/`에 써요. `docs/internals/`에는 여러 부분에 걸친 결정과 이유, 코드만 보고 놓치기 쉬운 제약을 써요. 코드의 필드·흐름을 나열하지 말고 원본에 연결해요. 현재 구조는 `structure/`에서 찾고, 진행 계획은 `devlog/`에 둬요. 결정이 바뀌면 기존 설명을 고쳐요.

## PR

문제와 바뀐 동작, 검증 명령과 결과, 남은 위험 및 실행하지 않은 검사를 적어요. 리뷰할 수 있도록 관련 결정과 범위를 연결해요. 푸시·PR 생성·병합은 요청이나 승인을 받은 뒤 해요.

## 구조

bun workspaces 모노레포예요. 서버는 `apps/server`(진입점 `apps/server/server.ts`), 웹은 `apps/web`, iOS 앱은 `apps/mobile`, 공용 계약은 `packages/contracts`, 저장소 lint 규칙은 `tools/oxlint-plugin-direction-board`, 서버 타입 오류 예산은 `tools/typecheck-budget`에 있어요. 실제 데이터 `data/`와 웹 빌드 기본 경로는 저장소 루트 기준이에요([apps/server/server/paths.ts](apps/server/server/paths.ts)). 이동 기록은 [이동 계획](devlog/_plan/261106_monorepo/README.md)에 있어요.
