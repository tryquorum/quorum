# 키보드 단축키

방향판 웹의 모든 단축키예요. 원본은 [apps/web/src/lib/shortcuts.ts](../../apps/web/src/lib/shortcuts.ts) 레지스트리이고, 화면의 도움말 패널(`?`, ⌘/·Ctrl+/, 문서 도구줄의 키보드 아이콘, ⌘K 의 "키보드 단축키")도 같은 목록에서 만들어요. 이 표와 레지스트리가 어긋나면 웹 시험(`shortcuts.test.ts`)이 실패해요.

## 규칙

- **한 글자 키**(n, /, d, ?, g, 1~4, Space, Enter)는 입력칸·편집기 안, 한글을 조합하는 중(keyCode 229 포함), 키를 누르고 있을 때, 창·메뉴가 열려 있을 때 먹지 않아요. 그래서 검색칸에 "n" 이나 "?" 를 쓰면 글자로 들어가요.
- **⌘·Ctrl 조합** 중 "입력 중" 칸이 "됨" 인 것만 입력칸 안에서도 먹어요(⌘K, ⌘/). ⌘B 는 편집기·입력칸에서는 굵게가 먼저라 사이드바를 접지 않아요.
- **n 은 화면 맥락**을 따라요: 문서 목록·문서 페이지에서는 새 문서, 나머지 화면에서는 빠른 추가(할 일). 리니어의 C, 노션의 새 페이지와 같은 생각이에요.
- **g 다음 글자**는 1.5초 안에 눌러요. g 다음 d 는 문서로 가고, 테마를 바꾸지 않아요.
- 맥(⌘)과 Windows·Linux(Ctrl) 표시는 도움말이 기기에 맞춰 바꿔 보여요. 판정은 ⌘·Ctrl 둘 다 받아요.

## 브라우저·OS 가 쓰는 키

이 키들은 앱 단축키로 쓰지 않아요(시험으로 확인): ⌘N·⌘T·⌘W(새 창·탭·닫기), ⌘L(주소창), ⌘D(북마크), ⌘1~9(탭 전환), ⌘⇧M(Chrome 프로필). Windows·Linux 의 Ctrl 조합도 같아요. 일부러 브라우저 기본 동작을 대신하는 키는 둘이에요: 순회 지시문 칸의 ⌘S·Ctrl+S(페이지 저장 대신 지시문 저장), ⌘K·Ctrl+K(Windows Chrome 의 주소창 검색 대신 팔레트, 페이지에 포커스가 있을 때). Firefox(Windows)의 Ctrl+B 북마크 사이드바는 페이지에 포커스가 있을 때 사이드바 접기가 먼저예요.

옛 화이트보드(보드 화면, iframe 안)는 따로 v·n·t·g·f·l·o 도구 키와 ⌘Z·⌘⇧Z·⌘D·Delete·Enter·Esc·⌘\ 를 써요. iframe 에 포커스가 있을 때만 먹어서 위 키와 섞이지 않아요. 이 표의 범위 밖이에요.

| 화면 이동 키가 없었어요 | g 다음 h·l·r·d·o·b |

## 다른 레인과 나눈 자리

- AI로 정리해서 올리기(`work/ai-capture`): 한 줄은 ⌘↵·Ctrl+Enter(`quickAdd.ai`, 한 줄에는 사람용 ⌘↵ 가 없었어요), 시트는 ⌘↵ 를 사람의 "추가" 로 그대로 두고 ⌘⇧↵·Ctrl+Shift+Enter(`sheet.ai`). 사람이 손에 익힌 시트 ⌘↵ 가 AI 실행으로 바뀌지 않게 나눴어요.
- ⌘,·Ctrl+, 는 설정창을 열어요(`settings.open`, `settings/panel` 레인에서 처리기를 붙였어요). 설정 › 단축키도 이 레지스트리에서 만들어요.
- 다른 레인은 레지스트리(`SHORTCUTS`, 얼려 둔 읽기 전용 목록)를 읽어 팔레트·설정에 보여 줄 수 있어요. 새 키는 이 목록에 더하고 이 표를 함께 고쳐요.
