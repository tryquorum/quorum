# 문서 계층(폴더식) 설계

독립 문서가 부모를 가질 수 있게 해요. 노션의 하위 페이지처럼 문서가 곧 폴더예요. 사이드바 트리, 브레드크럼, 이동, 열 보기 "폴더" 기준이 이 위에 서요. 결정 요약은 [ADR-0008](../../structure/decisions/ADR-0008-doc-hierarchy.md), 조사 근거는 [레퍼런스](../../devlog/_plan/261107_docs_plus_shortcuts_tree/evidence/refs.md), 작업·감사 기록은 [030](../../devlog/_plan/261107_docs_plus_shortcuts_tree/030_hierarchy_design.md)·[001](../../devlog/_plan/261107_docs_plus_shortcuts_tree/001_audits.md)이에요.

## 1. 모델

- **문서가 곧 부모**: `docs` 표에 칸 세 개를 더해요. `parent_id`(부모 독립 문서 id, NULL = 맨 위), `position`(형제 사이 순서, 정수), `archived_with`(부모와 함께 보관됐을 때 그 부모 ref). 색인 `docs(owner, parent_id)`. 별도 폴더 엔티티는 두지 않아요. 노션은 "폴더가 없다" 고 하고, 우리 독립 문서는 이미 본문·속성·태그·AI 대상이라 빈 그릇을 하나 더 두면 다룰 대상만 늘어요.
- **독립 문서만**: 부모도 자식도 `doc:` 문서만 돼요. 할 일·목표(판·영역), 사건(칸), 대화(실행 묶음)는 이미 자기 자리가 있어요. 이어 보려면 기존 링크를 써요. 나중에 넣으려면 ref 키 배치 표를 따로 더해요.
- **태그 경로**(`a/b`)는 그대로예요. 태그는 여러 곳·순서 없는 분류, 계층은 한 곳·순서·이동이 있는 위치예요.

## 2. 불변식 (저장된 그래프 전체, 보관 문서 포함)

- **순환 없음, 깊이 8단 이하**를 보관 여부와 상관없이 저장된 `parent_id` 그래프 전체에 지켜요. 그래서 되살리기는 그래프를 바꾸지 않고, 되살린 뒤에도 불변식이 그대로예요.
- 이동 검사: 새 부모의 저장된 조상 사슬(보관 포함, 재귀 CTE, 9단에서 끊음)에 대상이 있으면 409. "새 부모 깊이 + 대상의 저장된 하위 트리 높이(보관 자손 포함)" 가 8 을 넘으면 409.
- 보관된 문서를 새 부모로 고르거나, 보관된 문서를 옮기면 400(보관 문서는 되살린 뒤 옮겨요).
- **만들기도 같은 검사**를 해요: `parent` 를 준 만들기(REST·`/api/act`)는 같은 트랜잭션에서 부모가 owner 의 살아 있는 독립 문서인지(400·404), 부모 깊이 + 1 ≤ 8 인지(409) 보고, 실패하면 문서·태그·링크·멱등 기록까지 모두 롤백해요(시험: 8단 부모 아래 만들기 409, 아무것도 남지 않음).
- **살아 있는 문서의 부모는 살아 있거나 없음**(맨 위). 그래서 화면에 보이는 위치와 저장된 위치가 늘 같아요(아래 5절의 되살리기 규칙이 이것을 지켜요).

## 3. 순서

- `position` 은 형제 묶음(같은 owner·같은 `parent_id`) 안의 정수예요. 보이는 순서: `position` 오름차순(NULL 은 뒤), 같으면 제목, 그다음 ref.
- 형제 묶음에 쓰기(만들기·이동·빼내기) 전, 같은 트랜잭션에서 그 묶음을 **지금 보이는 순서대로 0, 1, 2… 로 다시 매겨요**(옛 문서의 NULL, 같은 값 모두 정리). 그다음 끼워 넣고 다시 매겨요. 형제 묶음은 수백 개 이하라 매번 다시 매겨도 싸고, 분수 키의 길이 증가·재균형 문제가 없어요.
- 이동 입력의 `before`·`after` 는 **하나만**(둘 다면 400). 자기 자신을 가리키면 400, 새 부모의 살아 있는 자식이 아니면 400. 둘 다 없으면 맨 뒤.
- 새로 만든 문서는 형제 맨 뒤. 다시 매기기를 포함한 모든 쓰기는 실패하면 함께 롤백해요(시험).

## 4. 이동 (`move`)

입력 `{ref, parent: ref | null, before?: ref, after?: ref}`. 한 `withDocsTx`(BEGIN IMMEDIATE) 안에서: ① 대상·새 부모가 owner 의 살아 있는 독립 문서(400·404) ② 불변식 검사(2절, 409) ③ 옛 형제 묶음과 새 형제 묶음 다시 매기기·끼워 넣기(3절) ④ `parent_id` 갱신 ⑤ 대상과 하위 트리 `reindexRef`. 노트 `version` 과 `updated_at` 은 올리지 않아요(이동은 내용 수정이 아니라 편집기 409 나 "최근 수정" 순서를 만들지 않음). 대신 색인 원본 서명에 계층이 들어가 바뀐 것을 알아봐요(9절).

두 연결이 A→B 아래, B→A 아래를 동시에 하면 둘째는 첫째의 쓰기 잠금 뒤에 다시 읽어 409. 화면은 이유를 그대로 보이고 트리를 다시 읽어요.

## 5. 보관과 되살리기

- `X` 를 보관하면 X 의 살아 있는 자손 중 `archived_with` 가 비어 있는 것을 같은 트랜잭션에서 보관하고 `archived_with='doc:X'` 를 남겨요. 이미 따로 보관된 자손(자기 `archived_with` 가 비었거나 다른 값)은 건드리지 않아요.
- `X` 를 되살리면 `archived_with='doc:X'` 인 자손만 함께 되살리고 표식을 지워요.
- 자손 `D` 만 따로 되살리면 D 의 표식을 지워요(이후 X 를 되살려도 D 는 이미 살아 있음). D 를 다시 따로 보관하면 표식 없이 보관돼요(X 를 되살려도 D 는 그대로).
- **연쇄는 상태가 실제로 바뀔 때만**: 이미 보관된 X 를 다시 보관하라는 요청(재전송)은 아무것도 바꾸지 않아요(개별로 되살린 자손을 다시 보관하지 않음). 이미 살아 있는 X 의 되살리기도 마찬가지예요.
- **되살린 자손은 맨 위로**: 부모가 보관 중인데 자손 D 만 되살리면, D 를 같은 트랜잭션에서 맨 위 형제 묶음의 맨 뒤로 옮기고(`parent_id=NULL`) D 의 표식을 지워요. "살아 있는 문서의 부모는 살아 있거나 없음" 이 지켜져서 화면 위치와 저장 위치가 같고, 맨 위 형제 정렬·before/after 가 한 묶음 안에서 돼요. 나중에 X 를 되살려도 D 는 X 의 자손이 아니라 그대로예요.
- **이동과 표식**: 살아 있는 D 를 옮기면 D 의 하위 트리에서 `archived_with` 가 D 의 새 조상이 아닌 문서를 가리키는 표식을 지워요(그 문서는 따로 보관된 것으로 남음). 되살리기는 언제나 "저장된 그래프에서 지금 X 의 자손이면서 표식이 X 인 문서" 만 함께 되살려요(시험: X 보관 → D 되살림(맨 위로) → D 를 다른 곳으로 이동 → X 되살림 → D 아래 보관 문서는 그대로).
- 시험: 중첩 보관(Y 따로 보관 → X 보관 → X 되살림 → Y 그대로), 자손만 되살림 → 맨 위로 옮겨짐, 보관 재전송이 되살린 자손을 다시 보관하지 않음, 자손 재보관, A(보관 자식 B 포함)를 깊은 곳으로 옮길 때 B 높이까지 세어 409, 보관 부모 경유 순환 시도 409.

## 6. 만들기와 `/api/act`

- REST `POST /api/docs` 에 선택 `parent`(`doc:` ref, 2절 검사). 멱등 해시: **`parent` 를 보낸 요청만** 해시에 넣어요. 생략한 요청의 해시는 지금 공식 그대로라, 배포 전에 저장된 요청을 옛 탭이 다시 보내도 같다고 봐요(시험: 옛 공식 해시가 저장된 요청의 재시도 성공, 같은 id 로 다른 parent 는 409).
- `/api/act` `{"do":"doc"}`: `parent` **생략은 지금과 똑같이** 보관 안 된 모든 독립 문서와 같은 제목 합치기(합쳐진 문서 위치는 안 바뀜). `parent: "doc:…"` 는 그 부모의 자식 중에서만 합치고 없으면 그 아래 만들기. `parent: null` 은 맨 위 문서 중에서만. 그 밖의 타입은 `{ok:false, error}`.
- `{"do":"move", ref, parent, before?, after?}` 를 더해요. 결과 `{ok, do:"move", ref}` 또는 이유.

## 7. `parent` 속성 이름

지금은 `parent` 가 쓸 수 있는 사용자 속성 이름이에요(`props.ts` `normalizeKey` 의 예약어 검사가 set·types·remove·검색 필터·속성 정렬 모두에 걸려 있음).

- 키는 NFC·trim·글자 규칙으로 문법을 검사해요. set·types 는 모든 예약어를 거절하고, remove·검색 필터·속성 정렬은 새 예약어 `parent`를 허용해요. 그래서 있던 `parent`(대소문자 변형 `Parent` 등 포함) 속성은 검색·정렬·정확한 키 삭제가 지금처럼 되고, 새로 만들거나 값을 바꾸는 건 400 이에요.
- 예외는 새 예약어 `parent`뿐이에요. 기존 예약어(`title` 등)는 검색·정렬·삭제에서도 종전처럼 400으로 기본 메타데이터 사용을 안내해요.
- `RESERVED_PROP_KEYS` 에 `parent` 를 더해요(대소문자 무시).
- 거울: 기본 `parent` 는 부모가 있을 때만 써요. 예약어와 대소문자 무시로 겹치는 사용자 속성은 `"<원래 키> (속성)"` 로 써요(YAML 키는 대소문자를 가르므로 `parent (속성)`·`Parent (속성)` 은 따로 남음).
- 마이그레이션이 이런 문서 수를 owner 별로 로그에 남겨요.
- 시험: 옛 `parent`·`Parent` 속성의 fetch·검색 필터·정렬·remove 성공, set 400, 거울 YAML 키 중복 없음.

## 8. 거울 (`data/vault`)

- **경로**: 맨 위 문서는 지금과 같은 `문서/<슬러그>--<해시16>.md`. 자식은 부모 파일 이름(확장자 뺀 것)을 그대로 폴더로 써요: `문서/<부모 파일 이름>/<자식>--<해시>.md`(옵시디언 "폴더 노트" 관례).
- **폴더 조각을 ledger 에 저장**: `Entry` 에 `folders: string[]`(실제로 쓴 폴더 이름들)를 더하고 `docPath(entry)` 는 이 조각으로만 경로를 만들어요. 그래서 ledger 검사(`journal.ts` 의 `e.path === docPath(e)`)는 DB·vault 루트 없이 스스로 검증돼요. 옛 항목(`folders` 없음)은 `[]` 로 읽혀 지금 경로와 같아요.
- **조각 고르기**는 sink(`createVaultSink(rootDir)`)가 entry 를 만들 때 해요: 조상 파일 이름을 맨 위부터 최대 4개, 절대 경로(`rootDir` + 상대 경로)가 UTF-8 1000바이트를 넘으면 넘지 않을 때까지 깊은 쪽 조각을 빼요. 맨 위 경로조차 넘치면 그 문서 거울 쓰기를 실패로 남겨요(지금 실패 경로). vault 루트가 바뀌면 rebuild 가 다시 골라요.
- **내용**: frontmatter `parent: "doc:…"` 는 부모가 있을 때만. 그래서 맨 위 문서의 내용·해시·서명은 바뀌지 않아 업그레이드 때 전체 다시 쓰기가 없어요. 예외는 `parent` 와 겹치는 사용자 속성을 가진 문서뿐이에요(7절의 키 이름이 바뀌어 그 문서만 한 번 다시 써요). `_index.md`·`_tags.md` 렌더링도 바꾸지 않아요(업그레이드 전에 남은 intent 가 새 코드의 렌더링과 어긋나지 않게).
- **하위 트리 전파와 부분 성공**: 이동·부모 제목 바꾸기·부모 보관/되살리기는 하위 트리 ref 를 모두 거울 큐에 넣어요. 큐는 지금처럼 ref 마다 따로 `upsert` 하고, 실패한 ref 는 재시도 표식을 남기고 다음 ref 로 가요. 곧 **부분 성공을 고른다**: 바깥에서 고친 거울 파일이 있는 ref 만 옛 경로에 남고 나머지는 옮겨져요. 이것은 지금도 모든 거울 쓰기에 적용되는 동작이에요.
- **충돌 파일 해소**: 바깥에서 고친 거울 파일은 rebuild 도 거절해요(`journal.ts:40`). 사람이 그 파일의 내용을 방향판 문서로 옮기거나 파일을 원래대로 되돌리면 다음 재시도가 지나가요. `docs/operations/` 에 절차를 적어요. 시험: 자손 하나의 파일을 고친 채 부모 이동 → 그 ref 만 실패·재시도 표식, 나머지 이동, 파일을 되돌린 뒤 재시도 성공.
- 시험: 루트 경로·내용 불변(옛 ledger 그대로 통과, 옛 intent 복구 통과), 자식 경로, 이동 시 옛 파일 삭제·새 파일, 부모 제목 바꿈 시 자손 경로 갱신, 1000바이트 넘치는 경로, 쓰기 도중 중단(intent 남김) 뒤 재시작 복구.

## 9. 변경 감지와 늦게 끝난 거울 쓰기

- 색인 원본 서명(`index.ts` 의 `signature`)에 `parent_id`·`position`·조상 파일 이름 사슬을 넣어요(부모가 없으면 지금 서명 그대로). 그래서 이동이 다른 쓰기 경로에서 일어나도 다음 `refreshChanged` 가 알아보고 다시 색인·거울 큐에 넣어요.
- 커밋 뒤 큐에 넣기 전에 서버가 죽으면, 다시 시작할 때 거울 전체 rebuild 가 맞춰요(지금 시작 규칙).
- 거울 완료 기록: `doc_index` 에 `folders`(JSON) 칸을 두고, sink 가 `mirror_path` 를 남길 때 `version` 과 함께 `folders` 도 같은지 봐요. 이동 뒤 늦게 끝난 옛 upsert 가 옛 경로를 기록하지 않아요. 시험: 연속 이동 중 지연된 upsert, 커밋 직후 중단.

## 10. 검색·읽기

- `search` 의 `parent`(REST `parent=root` 또는 `parent=doc:<id>`, 그 밖 400): 부모가 그 값인 **독립 문서만**(parent 를 주면 kinds 는 doc 로 좁혀요). `parent` 를 준 검색만 커서 해시에 `parent` 를 넣어요(다른 부모의 커서는 400). 생략한 검색의 커서 해시는 지금 공식 그대로라 배포 전 iOS·웹의 다음 쪽 요청이 계속 돼요.
- `sort=tree` 는 `parent` 와 함께일 때만(아니면 400). 형제 순서(3절)대로예요. 페이지 사이에 순서가 바뀌면 지금 다른 정렬과 같이 offset 커서라 밀릴 수 있어요(트리 화면은 펼칠 때 50개씩, 더 있으면 "더 보기").
- 결과 줄의 `parent`·`children`(살아 있는 자식 수)은 그 쪽의 id 들로 한 번의 `GROUP BY parent_id` 질의로 세요(색인 `docs(owner,parent_id)`).
- `fetch` 는 `ancestors`(맨 위부터 부모까지 `{ref,title}`)와 `frontmatter.parent` 를 줘요. 보관 문서를 읽으면 저장된 조상 사슬을 줘요(보관 표시와 함께).

## 12. MCP·운영 순회

- 도구 수는 7개 그대로. `board_search` 입력 strictObject 에 `parent`(string|null)·`sort: "tree"`, 출력 스키마에 `parent`·`children`. `board_fetch` 출력에 `ancestors`. `board_act` 설명에 `move` 와 `doc` 의 `parent` 세 가지 의미.
- 서버 instructions·ACT_GUIDE·운영 순회 지시문에 한 줄: "문서는 parent 로 계층을 가져요. 옮기기는 board_act move, 하위 문서는 doc 에 parent."

## 13. 화면

- **사이드바 트리**(문서 페이지의 "문서 트리" 섹션 안만 바꿔요; 사이드바 틀·검색·⌘K 는 건드리지 않음): 맨 위 문서 트리(`parent=root&sort=tree`), 펼침 상태는 이 브라우저에 기억, 자식은 펼칠 때 50개씩. 행에 마우스를 올리면 + (그 아래 새 문서)와 ⋯(이동…, 맨 위로). 끌어 옮기기: 행 가운데 = 그 아래로, 위·아래 4분의 1 = 앞·뒤로.
- **브레드크럼**: 문서 페이지 머리 "문서 / 조상… / 지금". 좁은 화면은 가운데를 "…" 로.
- **하위 문서 +**: 문서 페이지 머리 + 가 "하위 문서" (parent = 지금 문서). "이 문서와 연결" 은 끈 채로 고를 수 있게.
- **이동 대화상자**: 검색칸 + 들여쓴 목록(자기·자손·보관 제외) + "맨 위로". 키 `m`(문서 목록에서 고른 문서, 문서 페이지), 문서 페이지 ⋯ 메뉴 "이동…", 사이드바 ⋯.
- **열 보기 "폴더" 기준**: 첫 열은 맨 위 문서, 문서를 고르면 오른쪽에 그 자식 열.

## 14. 마이그레이션과 옛 클라이언트

- `initDocs` 가 칸·색인을 더해요(NULL = 맨 위, 데이터 옮김 없음). `doc_migrations` 에 `hierarchy-v1`, 옛 `parent` 속성 개수 로그.
