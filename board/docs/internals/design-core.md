# 디자인 코어

방향판의 색·글자·간격·층·모션·포커스·아이콘과 핵심 컴포넌트를 어떻게 쓰는지, 왜 그렇게 정했는지 적어요. 값 자체는 [토큰 원본](../../packages/design-tokens/src/index.ts)에 있고 여기에 옮겨 적지 않아요. 결정 기록은 [ADR-0009](../../structure/decisions/ADR-0009-design-tokens.md)예요.

## 원본과 소비

토큰 원본은 `packages/design-tokens` 의 TS 값이에요. 웹은 [index.css](../../apps/web/src/index.css)의 CSS 변수에 같은 값을 손으로 적고, [css-sync 시험](../../packages/design-tokens/src/css-sync.test.ts)이 두 쪽이 같은지 봐요. 빌드 단계를 늘리지 않으려고 CSS 를 만들어 내지 않았어요. iOS 는 [common.tsx](../../apps/mobile/src/common.tsx)에서 패키지를 바로 import 해요.

보드 화면은 옛 HTML([index.html](../../apps/server/public/index.html))을 iframe 으로 띄워 자체 CSS 변수 묶음(`:root`와 `html.dark`)을 쓰며, 부모 문서·저장소·시스템 테마를 따라 다크 모드로 함께 전환돼요. [사례 시험](../../packages/design-tokens/src/legacy-board.test.ts)이 라이트·다크 글자 색 대비와 포커스 링(`--ring` 2px)을 고정해요.

## 색

정체성은 흰 바탕(다크는 거의 검정), 검정 주 단추, 결정 빨강, AI 보라 ✦, 숫자 Geist Mono 예요. 의미가 있는 색만 색을 가져요.

- 의미 색은 두 단계예요. 점·아이콘·진행 막대처럼 글이 아닌 표시는 바탕 대비 3:1 이상인 기본 값(`done`, `running`, `warn`, `ai`, `decide`), 글자는 4.5:1 이상인 `*-foreground` 값을 써요. 라이트 `ai`(#8e51ff)는 아이콘 전용이라 글자에 쓰지 않아요.
- 결정 빨강(`decide`)과 오류(`destructive`)는 같은 빨강이에요. 색만으로는 둘을 가를 수 없어서 늘 글이나 아이콘을 함께 붙여요. 일 상세의 사건 칸에서 "지금"(급함)은 빨강, "결정 대기"는 노랑(`warn`), "진행"은 파랑이에요.
- 영역 색은 사람이 고른 데이터라 대비를 보장할 수 없어요. 그래서 점에만 칠하고, 점 옆이나 `sr-only` 로 이름을 늘 함께 둬요(색만으로 알리지 않기, WCAG 1.4.1).
- 틴트로 칸 전체를 칠해 강조하지 않아요. 매일 보는 칸이 늘 경보 색이면 진짜 급한 것과 구별이 안 돼요. 강조는 점·아이콘·글자 색과 무게로 해요.
- 장식용 왼쪽 세로선(묶음 표시선, 인용선, 타임라인 줄)은 쓰지 않아요. 같은 묶음은 머리글과 여백으로, 인용은 옅은 `muted` 바탕 블록으로, 기록은 점과 시각으로 보여요. 세로선은 패널·시트 경계, 시간 축(로드맵 날짜 줄·오늘 줄), 도구 단추 묶음 구분, 조작 손잡이처럼 기능이 있을 때만 남겨요. iOS 는 같은 규칙을 공용 스타일과 시험으로 지켜요([모바일 IA](mobile-ia.md#왼쪽-선과-위계)). 2026-11-07 전수 조사 표: [계획](../../devlog/_plan/261107_flicker_scroll/000_plan.md).
- 조작 경계(체크박스 테두리, 꺼진 스위치)는 `control` 로 바탕 대비 3:1 이상이에요. 장식 테두리(`border`)는 그보다 옅어도 돼요.
- 대비는 [시험](../../packages/design-tokens/src/tokens.test.ts)이 라이트·다크 모두 고정해요. 반투명 틴트 위 글자는 놓이는 바탕(배경·카드·muted·사이드바·사이드바 선택)에 sRGB 로 섞은 색으로 재요. css-sync 시험은 `:root`·`.dark` 의 색 변수 값만 비교해요(`@theme` 연결, 글자·간격·모션 값은 비교하지 않아요).

## 떠 있는 유리 표면

iOS 하단 탭의 떠 있는 표면은 iOS 26 이상에서 시스템 유리를 쓰고, 이전 버전에서는 블러 위에 반투명 바탕을 놓아요. 이 표면과 선택 표시의 [glass 토큰](../../packages/design-tokens/src/index.ts)은 웹 CSS 색 변수와 동기화하는 `color`와 용도가 달라 따로 두어요. 구현은 [TabPill](../../apps/mobile/src/TabPill.tsx)에 있어요.

## 글자

Inter 와 Pretendard 를 섞어 써요(라틴은 Inter, 한글은 Pretendard). 크기는 Tailwind 기본 단계에 `text-2xs`(11px)를 더한 것만 쓰고, 11px 아래는 쓰지 않아요(Apple HIG 의 최소 크기와 같은 생각). 13px 단계는 만들지 않았어요: 클래스 병합(`cn`)이 `text-ui` 같은 새 이름을 색으로 읽어 다른 색 클래스와 부딪혔어요.

한국어 본문은 줄간격 1.6~1.7, 조작 글은 1.4 쯤이에요. 굵기는 400·500·600 만 써요. 고정폭 `num`(Geist Mono)은 숫자만 있는 값(개수, 09:00)에만 쓰고, "11. 7. (토) 오후 2:03"처럼 한국어가 섞인 날짜는 `tnum`(본문 글꼴 + 같은 폭 숫자)을 써요.

## 간격·반경·층·모션

간격은 4px 단위예요(Tailwind 기본). 반경은 sm 6 · md 8 · lg 10 · xl 14 px 이고 카드·입력은 lg 예요. 겹침 순서는 sticky 10 · raised 20 · AI 정리 트레이 30 · AI 명령창 40 · 덮개 50 · 토스트 60 이고, 그림자는 떠 있는 것(팝오버·시트·AI 명령창·트레이)에만 써요. 모션은 120ms(누름·호버), 200ms(팝오버·시트 열림), 280ms(큰 시트)이고, 사람이 움직임 줄이기를 켜면 모든 전환을 거의 0 으로 줄여요.

대화상자·시트의 덮개는 `overlay` 토큰 단색으로 가볍게 어둡게 해요(라이트 `#0a0a0a24` 약 14%, 다크 `#00000073` 약 45%). 뒤 화면을 흐리게 하는 `backdrop-filter` 는 쓰지 않아요: 덮개가 열린 동안 화면 전체를 매 프레임 다시 칠해, 같은 조건 실측에서 팝업이 열린 동안의 프레임이 홈의 1/2~1/3 로 떨어졌어요.

## 스크롤

스크롤 막대는 얇게, 바탕 없이 그려요. 평소엔 옅은 `scrollbar`, 가리킨 영역과 스크롤하는 동안의 영역은 `scrollbar-active`(놓이는 바탕 대비 3:1, 토큰 시험)예요. 스크롤 중 표시는 [scroll-activity](../../apps/web/src/lib/scroll-activity.ts)가 이벤트를 받은 요소에 `data-scrolling` 을 잠깐 붙여서 해요. 문서는 테마별 `color-scheme` 을 가져 브라우저 기본 조작도 테마를 따라요. 일 상세의 독립 스크롤 칸은 `.scroll-pane`(끝에 닿아도 바깥이 끌려 움직이지 않음, 막대가 생겨도 폭 고정)이에요.

`scroll-behavior: smooth` 는 전역으로 주지 않아요. 대화 창·AI 명령창의 바닥 고정, 목록 키보드 이동, 편집기 커서 따라가기는 즉시 움직여야 해요. 일부러 부드럽게 옮기는 곳(문서 개요 이동)은 움직임 줄이기를 켜면 즉시로 바꿔요.

## 포커스

키보드 포커스는 모든 요소에서 한 가지로 보여요: `--ring` 단색 2px. Tailwind 층 순서 때문에 컴포넌트의 `outline-none`(utilities)이 index.css 의 기본 `:focus-visible` 외곽선(base)을 이겨요. 그래서

- 링을 그리는 컴포넌트는 `outline-none focus-visible:ring-2 focus-visible:ring-ring` 을 함께 써요. 주 단추는 링과 단추 사이에 바탕 간격(`ring-offset-2`)을 둬서 검정 단추 둘레에서도 보여요.
- 따로 정하지 않은 요소(패널 안 링크·버튼)는 기본 2px 외곽선을 받아요.
- 편집 본문(Tiptap)은 포인터·터치로 누르면 깜박이는 커서만 보여요(쓰는 동안 테두리가 방해돼요). 글 입력 영역은 브라우저가 늘 `:focus-visible` 로 보므로, 들어올 때의 마지막 입력([input-modality](../../apps/web/src/lib/input-modality.ts))으로 가려 키보드로 들어오면 본문 둘레에 같은 2px `--ring` 외곽선을 보여요.
- 문서 제목 입력칸은 화면을 옮길 때 앱이 포커스를 줘요. 글 입력칸은 브라우저가 늘 키보드 포커스로 보므로, 포인터로 문서를 연 경우에만 그 첫 포커스의 링을 숨기고(깜박이는 커서는 보여요) 키를 누르거나 다시 누르면 링이 돌아와요. 키보드로 열었거나 마지막 입력을 모르면 링을 보여요([input-modality](../../apps/web/src/lib/input-modality.ts)).
- 링 색을 반투명이나 다른 색으로 바꾸지 않아요. [focus-rule 시험](../../apps/web/src/lib/focus-rule.test.ts)이 컴포넌트의 큰따옴표 클래스 문자열을 읽어 같은 문자열 안의 규칙(단색 링, 링이면 outline-none, 링과 외곽선 겹침 없음)을 지켜요. 작은따옴표·템플릿 문자열과 조상·자손 사이의 겹침(예: AI 명령창의 `focus-within` 링과 안쪽 단추의 외곽선)은 보지 않아요.
- 보드 iframe([index.html](../../apps/server/public/index.html))도 같은 `--ring` 2px 외곽선 규칙을 따르고 [legacy-board 시험](../../packages/design-tokens/src/legacy-board.test.ts)이 지켜요.

## 아이콘

lucide 아이콘만 써요. 크기는 14·16·20px(`size-3.5`·`size-4`·`size-5`)이고 글과 같은 색이에요. 아이콘만 있는 단추에는 `aria-label` 과 툴팁을 같이 둬요. ✦(`AiMark`)는 AI 가 하는 동작과 AI 가 만든 것 표시에만 써요.

## 핵심 컴포넌트

| 컴포넌트 | 쓰는 규칙 |
|---|---|
| 단추 | 한 구역에 채운 주 단추 하나, 나머지는 테두리·고스트. 주된 선택은 크기가 아니라 스타일로 구별해요 |
| 칩 | 필터(눌러서 거르기), 상태(끝남·열림 등, 의미 색 틴트 + foreground 글자), 출처(GitHub 등, 회색). 셋을 섞지 않아요 |
| 행 | 할 일·사건·문서 행은 왼쪽 표시(체크·출처) → 제목 → 오른쪽 메타(날짜 `num`/`tnum`). 동작은 호버·포커스에 보이고, 터치 기기에선 늘 보여요 |
| 시트·대화상자 | 데스크톱은 가운데 대화상자, 768px 미만은 아래 시트 |
| 팝오버·메뉴 | 고르기·짧은 설정. 긴 입력은 시트로 |
| 빈 상태 | 왜 비었는지 한 줄 + 다음 동작 하나 |
| 로딩 | 모양을 아는 곳은 스켈레톤, 짧고 모르는 기다림은 진행 표시. 가짜 완료를 보이지 않아요 |
| 오류 | 이유 한 줄 + 다시 시도 또는 고칠 곳. 같은 실패를 두 곳에 띄우지 않아요. 이전 내용을 보여 줄 수 있는 실패(새로고침 실패)는 일을 막지 않으니 화면 위 조용한 한 줄(`role="status"`)이고, 출처가 여럿이면 "보드·소식을…" 처럼 한 줄·한 단추로 합쳐요. 보여 줄 내용이 없는 실패만 테두리 카드(`role="alert"`)예요([data-state](../../apps/web/src/components/data-state.tsx)) |
| 페이지 제목 | 768px 미만에서 머리글 맨 윗줄이 같은 이름을 보여 주면 큰 제목은 눈에서 숨겨요(`PageHeader echoesHeader`, 읽기 프로그램·화면 이동 포커스용으로는 남김). 제목이 다른 정보(홈의 날짜)면 그대로 둬요 |
| 토스트 | 되돌릴 수 있는 결과나 화면 밖에서 끝난 일만 |
| 입력 | 테두리는 `input`, 포커스는 링. 날짜는 한국어 형식으로 보여요(개선 진행 중) |
| 접는 절 | 요약 한 줄 단추(`aria-expanded`)로 접어요. 저장 안 된 값·오류·저장 중이면 늘 펼치고 접을 수 없어요(문서 속성: [doc-meta-fold](../../apps/web/src/lib/doc-meta-fold.ts)). 위험이 풀려도 저절로 접지 않아요 |
| AI 입구 | 머리글 오른쪽의 AI 단추(✦, 768px 이상은 "AI" 글 함께) 하나와 `/` 예요. 모든 화면이 같은 자리·같은 모양이고, 열면 오른쪽 아래에 명령창이 떠요. 할 일을 AI로 정리하는 것은 빠른 추가 줄의 ✦ 가 맡아요 |
| AI 정리 트레이 | 빠른 추가 줄이 있는 화면(홈·전체 목록)은 그 줄 아래에, 없는 화면은 아래 오른쪽에 떠요. 떠 있는 동안 그 높이(`--tray-space`)만큼 본문 끝에 자리를 내줘 마지막 줄이 가리지 않아요. 아래에 도구줄이 있는 보드만 위 오른쪽이에요. 머리와 제목은 가리지 않아요 |

## 누름 영역

손가락으로 누르는 조작(단추·체크·스위치·탭)은 44px 이상이에요(Apple HIG). 768px 미만이거나 터치 포인터(`pointer: coarse`)이면 공용 단추·사이드바 메뉴가 44px 높이가 되고, 체크박스·스위치는 보이는 크기를 그대로 두고 누름 영역만 44px 로 넓혀요. 체크가 있는 행은 같은 조건에서 행 높이도 44px 이상이고 제목 단추가 행 높이를 채워서, 이웃 행과 누름 영역이 겹치지 않고 행 어디를 눌러도 반응해요. 공용 단추를 쓰지 않는 단추(목록 행의 별, 로드맵 보기 고르기, 일 페이지의 모바일 탭 등)도 같은 조건을 따로 적어요. 글 사이의 제목 링크는 24px 이상이면 돼요(WCAG 2.5.8).

## lint 와 시험이 지키는 것

[no-raw-style](../../tools/oxlint-plugin-direction-board/rules/no-raw-style.ts)이 `apps/web/src`·`apps/mobile/src` 의 문자열에서 팔레트 직접 색 클래스(`text-amber-500` 등), 임의 글자 크기(`text-[11px]`), 색 리터럴을 막아요. 남겨 둔 것은 [기준선](../../tools/oxlint-plugin-direction-board/raw-style-baseline.json)에 정확한 문자열로 적혀 있고(iframe 미리보기 CSS 처럼 변수를 못 받는 곳), 하나를 없애면 기준선에서도 지워야 해요. 이어 붙여 만든 클래스(`text-${c}-500`)와 CSS 파일·옛 HTML 은 이 규칙이 못 봐요. CSS 변수는 css-sync 시험이, 옛 HTML 은 사례 시험이 맡아요.
