# AI 실행과 대화

[실행기](../../apps/server/server/runs.ts)는 `aside exec`로 시작하고 이어 묻기는 Aside 세션을 이어요. 명령창과 ⌘K는 기본적으로 새 대화예요(`aa5fc33`). 지난 대화는 명시적으로 골라야 해요. [실패 분류](../../apps/server/server/run-errors.ts)는 중단·실행 파일·Aside 연결·인증·한도·모델·네트워크 등을 구분해요.

다시 시도는 원본 실행당 한 번 새 대화로 만들어요. 재시도는 처음 저장한 화면 지정으로 현재 자료를 다시 읽고, 이어 묻기도 보낼 때마다 화면 맥락을 다시 만들어요. 그러므로 처음 봤던 내용의 불변 스냅샷이라고 생각하면 안 돼요. [화면 맥락](../../apps/server/server/page-context.ts)은 ref와 보이는 대상이 무엇인지 설명해요.

## AI로 할 일 추가(capture)

빠른 추가의 ✦ 는 실행 종류 `capture` 를 시작해요([capture.ts](../../apps/server/server/capture.ts)). 지시는 같은 일 찾기 → 사실 확인 → `/api/act?run=<id>` 로 올리기 → 결정은 `decide` 순서예요. 코드만 보고 놓치기 쉬운 결정은 이래요.

- **바로 만들고 되돌리기**: 미리보기 승인 없이 올려요. 실행이 분 단위라 사람이 기다렸다 승인하는 흐름은 "사람 대신" 이라는 목적과 맞지 않아서예요([레퍼런스](../../devlog/_plan/261107_ai_capture/evidence/refs.md)).
- **실행에 묶기**: `?run=` 이 붙은 쓰기만 결과(`run_effects`)에 묶여요. 로컬 리스너, 에이전트 토큰 아님, 같은 주인, `capture`, `running` 일 때만 받아요. 로컬 리스너가 이미 인증 없는 신뢰 경계라 별도 열쇠는 두지 않아요(지시문·단계 기록으로 새기만 해요). 그래서 늦은 쓰기 차단은 `run` 이 붙은 요청에만 보장돼요. 액션마다 적용과 기록을 `withDocsTx` 하나로 묶어 기록하지 못하면 적용도 되돌려요.
- **되돌리기 지문**: 기록할 때 항목 `seq`, 문서 내용(노트 본문·사람 수정 표시·속성 값과 쓴 이·사람과 에이전트 태그의 해시, 색인이 올리는 `version` 은 쓰지 않음), 사건 `updated_at` 을 남겨요. 실행에 묶인 액션마다 적용 직전에 계보의 지문과 지금을 비교해 달라졌으면 `touched` 로 영구 표시하고, 되돌릴 때 같은 트랜잭션에서 지문·`touched`·사람 태그와 속성을 다시 확인해요. 계보 밖에서 이미 열려 있던 결정을 다시 쓴 것(`preexisting`)도 되돌리지 않아요. 기존 일에 덧붙인 것은 되돌리지 않아요.
- **결정 중복**: `decide` 의 사건 ref 는 질문 제목 정규화(`decide:<normTitle>`)라 다시 시도해도 같은 질문은 같은 사건을 갱신하고, 이미 닫힌 질문은 다시 열지 않아요.
- **중복 제출**: 화면이 보내는 `clientKey` 가 같으면 같은 실행을 돌려주고(응답 유실), 다른 키라도 같은 글이 도는 중이거나 10분 안에 끝났으면 409 와 그 실행을 돌려줘요. 검사와 INSERT 사이에 await 이 없어 한 서버 프로세스 안에서는 겹치지 않아요.
- **출처**: 만든 할 일은 `agent: true`, `capture: <run>`(사람 PUT 도 지우지 않고 화면이 보낸 값은 버림), `ai-추가` 태그, `run:<thread>` "AI 정리" 연결을 가져요.
