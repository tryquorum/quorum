Quorum — 필요한 일만 하는 에이전트 의회

스펙 v0 · 2026-11-09 · c0mpiled-17: Seoul · YC RFS: Multiplayer AI + Self-Maintaining APIs · 방향판 + Aside + gbrain + gstack

한 줄 요약. 여러 봇이 할 일을 제안하고 서로 반박해서 정말 필요한 일만 통과시켜요. 통과한 일은 Aside가 로그인된 브라우저에서 실행하고, gbrain이 판정을 기억해 다음 비슷한 요청에 같은 판단을 바로 내려요. 사람은 방향판에서 결과와 승인 대기만 봐요.

1. 문제

  • 에이전트가 늘수록 제안과 알림도 늘어나요. 대부분은 필요 없는 일이고, 사람이 하나하나 걸러야 해요.
  • 에이전트가 같은 판단을 매번 처음부터 다시 해요. 어제 기각한 일을 오늘 또 제안해요.
  • 공식 API가 없는 사이트를 다루는 자동화는 경로 하나만 바뀌어도 조용히 깨져요.

2. 구성

구성역할연결 방식
방향판
(기존 서비스)		사건 수신, 사람 승인 칸, 결과 노트. 사람이 보는 화면REST /api/act, MCP board_search · board_fetch · board_act · board_write. 코드는 복사하지 않고 실행 중인 서비스를 호출
Aside로그인된 브라우저에서 실행하고 결과 확인. 깨진 경로 재탐색aside repl(정해진 단계), aside exec(판단·로그인 필요)
gbrain판정과 근거, 레시피 버전을 출처와 함께 기억. 비슷한 사례 회상gbrain init --pglite, search/think, MCP
gstack반박하는 봇 역할: CEO(필요한가), 리뷰어(중복·버그), QA(실제로 되나), CSO(위험)gstack 스킬을 봇 프롬프트·역할로 사용(--host codex/claude)
Quorum
(오늘 만드는 것)		의회 오케스트레이터, 레시피 자가수리, 데모 화면새 저장소, 10:00 이후 커밋만

3. 흐름

① 수신방향판 사건 또는 사람 요청이 들어와요
② 회상gbrain에서 비슷한 지난 판정을 찾아요
③ 제안제안 봇 2–3개가 할 일 후보를 내요
④ 반박gstack 역할 봇이 각 후보를 필요성·중복·위험으로 까요
⑤ 판정통과/보류/기각과 이유. 위험이 높으면 방향판 승인 칸으로
⑥ 실행·기억Aside가 실행·확인하고, gbrain과 방향판에 판정·결과·출처를 남겨요

회상에서 거의 같은 판정이 나오면 ③–④를 건너뛰고 "지난번 판단 재사용"으로 바로 판정해요. 이 장면이 데모에서 기억의 가치를 보여 줘요.

4. 스스로 고치는 API (레시피)

  • 레시피 = 사이트, 의도(예: "행사 공지 읽기"), 경로, 응답 파싱 규칙, 검증 예시.
  • 깨짐 감지: 404, 스키마 불일치, 빈 결과가 검증 예시와 다를 때.
  • 수리: Aside가 실제 페이지를 열어 네트워크 요청을 관찰하고 새 경로 후보를 찾아요. 검증 예시를 통과한 후보만 새 버전으로 저장하고, 이전 버전과 깨진 이유를 gbrain에 남겨요.
  • 실제 사례: 오늘 Luma 공지를 읽을 때 event/get-posts는 404였고, 재탐색으로 event/get-blasts를 찾아 공지 7개를 읽었어요.
